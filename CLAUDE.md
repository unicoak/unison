# CLAUDE.md — Прокачка

Рабочий файл для Claude Code (и для человека) — что это за проект, как он устроен,
на чём стоит в проде и какие грабли уже случались, чтобы не наступать на них снова.

**Правило:** этот файл коммитится в публичный репозиторий `unicoak/unison` на GitHub.
Никогда не писать сюда реальные пароли, токены, ключи — только имена переменных.
Настоящие значения — в `.env` (gitignored) и в переменных окружения приложения на Timeweb.

## Что это

Платформа для проведения уроков: логин/пароль, роли ученик/учитель/бог, квесты вместо
домашки, опыт и уровни, ачивки, расписание и учебный план на год. Подробности — в README.md.

## Стек

Next.js 15 (App Router) · TypeScript · Tailwind CSS v4 · Prisma + PostgreSQL · Auth.js
(credentials) · Zod · framer-motion · @aws-sdk/client-s3

## Прод-окружение (Timeweb Cloud)

- **Хостинг приложения:** Timeweb Cloud Apps, автодеплой из GitHub (`unicoak/unison`, ветка `main`)
- **База данных:** Timeweb Managed PostgreSQL, приватный адрес `192.168.0.4:5432` (доступен
  только изнутри той же приватной сети Timeweb — с локальной машины не подключиться, это нормально)
- **Приватная сеть (VPC):** `192.168.0.0/24` — и база, и приложение должны быть в ней,
  иначе приложение не достучится до базы
- **Файлы домашек:** Timeweb S3 (`s3.twcstorage.ru`, регион `ru-1`)
- **Текущий публичный адрес:** периодически меняется (см. ниже про удаление приложения) —
  актуальный уточнять у пользователя, а не считать намертво зафиксированным
- **Build command:** `npm run build`
- **Start command:** `npm start` (= просто `next start`, см. «Грабли» ниже — это важно, не менять не подумав)

Нужные переменные окружения — см. `.env.example`. Реальные значения хранятся у
пользователя локально в `.env` и в панели Timeweb (App Platform → приложение → Settings → Variables).

## Роли и доступ

- **Ученик** — регистрируется сам (`/register`)
- **Учитель** — создаётся только повышением роли ботом (`GOD`) в `/dashboard/manage/users`,
  самостоятельно зарегистрироваться учителем нельзя
- **Бог** — создаётся сид-скриптом (`prisma/seed.ts`) из `GOD_EMAIL`/`GOD_PASSWORD`/`GOD_NAME`

## Известные грабли (важно прочитать перед изменением деплоя/старта)

1. **Миграции и сид НЕ должны быть в `npm start`.**
   Раньше `start` был `prisma migrate deploy && npm run seed && next start`. На тарифе
   с 1 ГБ RAM это приводило либо к OOM (`Killed` в логах), либо к тому, что сайт не
   успевал ответить на health-check Timeweb (проверка каждые 30 сек, 3 неудачи подряд →
   автоперезапуск) — получалась бесконечная карусель "Ready" → SIGTERM → рестарт.
   Схема и сид уже применены к текущей базе. Если понадобится накатить новую миграцию —
   процедура описана в README.md («Миграции и сид на проде»), кратко: временно вернуть
   `prisma migrate deploy && npm run seed && next start` как Start command, дождаться
   одного успешного деплоя, вернуть обратно на `npm start`.

2. **Файлы домашек — только через S3, не на локальный диск.**
   `/app/public` в контейнере доступен только на чтение — попытка писать туда падает с
   `EACCES: permission denied`. `src/lib/storage.ts` шлёт файлы в S3 при заданных `S3_*`
   переменных; локальный диск (`/tmp`, через `/api/uploads/[filename]`) — только dev-фолбэк,
   в проде не переживает перезапуск/передеплой.

3. **Auth.js требует `trustHost: true`** (`src/auth.config.ts`) — без этого на любом
   хостинге кроме Vercel вход падает с общей ошибкой «There was a problem with the server
   configuration».

4. **API Timeweb не стоит дёргать слишком часто/параллельно.**
   Несколько деплоев подряд за короткое время (ручной триггер поверх автодеплоя от пуша)
   один раз реально подвесило очередь деплоя на несколько часов. Если деплой не завершается
   за 5-7 минут — не долбить API повторно, лучше подождать или проверить в самой панели.

5. **Приложение в Timeweb может быть удалено и пересоздано пользователем** — тогда меняется
   и домен (`*.twc1.net`), и внутренний app_id. База данных и S3-бакет при этом не трогаются,
   данные не теряются. Всегда уточнять текущий домен, не полагаться на записанный в истории.

## Структура проекта

- `prisma/schema.prisma` — модель данных
- `prisma/migrations/` — миграции (сгенерированы офлайн через `prisma migrate diff`,
  без живого подключения к БД — см. историю, если понадобится генерировать ещё)
- `prisma/seed.ts` — лестница уровней, стартовые ачивки, аккаунт бога
- `src/lib/` — бизнес-логика (XP/уровни, ачивки, доступы, `storage.ts`, валидация)
- `src/app/(auth)/` — вход/регистрация
- `src/app/dashboard/` — личный кабинет ученика и `dashboard/manage/*` (учитель/бог)

## Журнал изменений

### 2026-09-03 — Инициализация MVP (`5910a0a`)
Первая версия с нуля: Next.js 15 + Prisma/PostgreSQL + Auth.js, роли ученик/учитель/бог,
XP/уровни/ачивки, квесты с проверкой домашки, расписание, учебный план. Дизайн —
осознанно неo-brutalist (не типовой ИИ-шаблон), шрифты Unbounded + Golos Text.

### 2026-09-03 — Фикс входа на не-Vercel хостинге (`af8db8f`)
Добавлен `trustHost: true` — без него Auth.js v5 отклоняет Host-заголовок на любом
хостинге, кроме автоопределяемого Vercel, вход падал с generic-ошибкой конфигурации.

### 2026-09-03 — Защита секретов от случайного коммита (`e30000a`)
В `.gitignore` добавлены `*.env`/`env.env` — обнаружился файл-копия `.env` с реальным
паролем бога, не попадавший под старые правила игнора.

### 2026-09-03 — Фикс загрузки файлов на read-only ФС (`9144477`)
Домашки с фото падали с `EACCES: permission denied, mkdir '/app/public'` — контейнер
даёт только чтение на `/app/public`. Временное решение — писать в `/tmp` и отдавать
через `/api/uploads/[filename]`.

### 2026-09-03 — Переход на S3 вместо временного диска (`93e8e7e`)
По просьбе пользователя сделано нормальное решение вместо заплатки: файлы уходят в
Timeweb S3 (path-style, `s3.twcstorage.ru`, регион `ru-1`) через `@aws-sdk/client-s3`.
Заодно убран неиспользуемый `@vercel/blob` (деплой на Vercel не планируется).

### 2026-09-03 — Попытка запускать миграции в фоне (`085c800`)
Первая попытка починить карусель перезапусков: `next start` сразу, миграции/сид —
параллельно в фоне. Не помогло полностью — в логах обнаружились `Killed` (OOM) на
тарифе 1 ГБ RAM.

### 2026-09-04 — Упрощение до голого `next start` (`6d0ada5`)
Итоговый фикс: `npm start` теперь только `next start`. Миграции/сид не гоняются на
каждом запуске (БД уже была накатана предыдущими успешными запусками) — так снят и
риск OOM, и риск не успеть пройти health-check вовремя. Для будущих миграций — см.
«Известные грабли» выше.

### 2026-09-27 — Пересоздание приложения на Timeweb
Пользователь удалил приложение из-за зависшей очереди деплоя, пересоздали с нуля по
той же схеме (тот же репозиторий/ветка, те же переменные окружения, та же приватная
сеть). Новый домен, но база и S3-бакет — те же, данные не потерялись. Всё заработало
с первого раза, без зависаний — подтверждает, что фикс от 2026-09-04 решил проблему.

### 2026-09-27 — Сброс пароля богом (`53902a8`)
В `/dashboard/manage/users` добавлена возможность богу сбросить пароль любому
пользователю (включая себе). Показ текущего пароля НЕ реализован и не планируется —
пароли хранятся как bcrypt-хеш (`passwordHash`), обратное восстановление невозможно,
а хранить/показывать пароли в открытом виде — дыра в безопасности.

### 2026-10-04 — Удаление квестов и учеников
Учитель и бог могут удалять квест (кнопка на странице квеста) и ученика (кнопка на
странице ученика), с подтверждением через `confirm`. Связанные данные (назначения, сдачи,
профиль, ачивки) удаляются каскадом на уровне БД, миграция не нужна. Уже начисленный XP за
удалённый квест НЕ откатывается. Файлы сдач в S3 не удаляются (остаются сиротами в бакете).

### 2026-10-04 — Создание и редактирование ачивок
Новая страница `/dashboard/manage/achievements` (учитель и бог, пункт «Ачивки» в меню):
создание и правка названия/описания/иконки. `code` при правке не меняется (по нему
авто-выдача ищет ачивку); у новых ачивок он `custom-<uuid>`. Удаление ачивок не делалось.
Внимание: `prisma/seed.ts` делает `upsert` по `code` с `update`, поэтому повторный сид
перезапишет правки стартовых ачивок.

### 2026-10-04 — Форум
`/dashboard/forum` (список тем), `/new` (создание темы с первым сообщением), `/[id]`
(тема и ответы). Доступно всем ролям, пункт «Форум» в меню. Модели `ForumTopic`/`ForumPost`,
автор с `onDelete: Cascade` (удаление ученика убирает его сообщения). Модерации/удаления
сообщений нет. **Нужна миграция** `20261004120000_forum` — до её применения на проде
страницы форума будут падать; процедура — в README («Миграции и сид на проде»).

### 2026-10-04 — Колонтитул с версией
Компонент `src/components/SiteFooter.tsx` (лендинг, вход/регистрация, дашборд): название
организации (`ORGANIZATION` в `src/lib/brand.ts`), версия, короткий хэш коммита (если на
сборке есть git) и время сборки по МСК. Версия — `version` в `package.json`, **поднимать

`next.config.ts` при каждой сборке, так что по ним видно, что деплой применился.

### 2026-10-06 — Ачивка за квест
У квеста есть необязательная `Quest.achievementId` (выбирается в форме создания квеста).
Когда учитель принимает работу (`APPROVED`), ученик автоматически получает эту ачивку
(`grantQuestAchievement` в `src/lib/achievements.ts`, идемпотентно). Редактирования уже
созданных квестов нет, привязка — только при создании. **Нужна миграция**
`20261006120000_quest_achievement`: колонка добавляется в `Quest`, поэтому до её применения
ломаются ВСЕ страницы с квестами (Prisma выбирает несуществующую колонку) — порядок
выкатки: сначала Start command с `prisma migrate deploy`, потом пуш (см. README).
Способы выдачи ачивок в целом: вручную (страница ученика), авто по коду (`first-quest`,
`five-quests`, `level-5`), и теперь привязанная к квесту.
